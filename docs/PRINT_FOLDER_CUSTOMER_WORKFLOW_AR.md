# سير عمل Golden Target: واتساب + مجلدات الطابعات + done + الذمم

هذه الميزة **لا تستخدم الذكاء الاصطناعي لقراءة محادثات العملاء**؛ ولا تنشئ أمر إنتاج تلقائياً من كلام العميل.

## خطوات العمل

1. يرسل العميل التصميم على واتساب، أو يضيفه الموظف يدوياً. عند الربط الرسمي بـ WhatsApp Business Platform، يمكن تسجيل أرقام المرسلين في العملاء. لا يمكن قراءة دفتر عناوين تطبيق واتساب العادي مباشرة باستخدام Cloud API.
2. عند إضافة عميل، يعتمد التطابق أولاً على رقم الهاتف بعد توحيده لصيغة دولية؛ يحتفظ بالاسم المسجّل سابقاً، ويعرض الاسم نفسه مع رقم مختلف للمراجعة. يمكن أيضاً استيراد جهات اتصال الهاتف كملف CSV (اسم، رقم الهاتف). هذه ليست مزامنة مستمرة لدفتر واتساب.
3. يحرر المصمم ملف التصميم وينقله بالطريقة الحالية إلى \`basePath/<dateFolder>/<printer>/<filename>\`. لا ينقل البرنامج الملفات تلقائياً.
4. تظهر ملفات الطباعة في Kanban. يمكن ربط ملف أو أكثر بالعميل وطلب التصميم.
5. عند نقل الملف إلى \`basePath/<dateFolder>/<printer>/done/<filename>\` بنفس الطابعة، يسجل البرنامج اسم الملف والطابعة وتاريخ المجلد ووقت **أول رصد داخل done**، وليس وقت الطباعة الفعلي من عداد جهاز الطابعة. يظل السجل محفوظاً في SQLite إذا لم يعد الملف مرئياً لاحقاً.
6. مقدار الطباعة **لا يستنتج تلقائياً إن كان غير مذكور صراحة في اسم الملف**. يظهر حقل الكمية فارغاً ويصححه المستخدم يدوياً. أبعاد الطباعة تُقرأ من اسم الملف إذا كانت بصيغة معروفة، ويمكن تعديلها.
7. داخل «سجل ملفات الطباعة» يمكن تعيين العميل، العدد، المقاس، المادة، السعر الاختياري، المبلغ المدفوع، الملاحظات، وحساب المتبقي = السعر − المدفوع. لا يُنشئ السعر الاختياري فاتورة آلياً، تفادياً للازدواج في حسابات النظام القديمة.

### ملاحظة عن إعادة تسمية الملفات

يستخدم السجل بصمة metadata مؤلفة من مجلد التاريخ والطابعة ووقت إنشاء الملف والحجم لمحاولة وصل الاسم الجديد بالسجل القديم. عند التطابق الفريد، يبقى السجل ذاته وتُحفظ الأسماء السابقة. قد تتغير البصمة عند نسخ الملف إلى قرص آخر أو أثناء تعديل محتواه، وفي هذه الحالة يحتاج المستخدم مراجعة الربط يدوياً. لا يتم دمج الملفات المتعددة ذات البصمة المكررة بصورة تخمينية.

### تسجيل المزامنة

- **واتساب Business Platform الرسمي:** عند إعداد API وWebhook، ينشئ البرنامج سجل العميل أو يربطه بواسطة رقم المرسل الموجود في الحدث. التطابق بالاسم فقط لا ينتج دمجاً آلياً.
- **جهات الاتصال الموجودة سلفاً على الهاتف:** تصديرها من جهات اتصال Android / Google Contacts كـ CSV، ثم استيرادها من «واتساب واستلام التصاميم».
- **المحادثات القديمة وجهات اتصال واتساب الشخصية بالكامل:** ليست قابلة للاستخراج عبر Cloud API دون إعدادات ومنتجات/إجراءات منفصلة. لا تستخدم WhatsApp Web scraping أو جلسات QR غير رسمية لهذا الغرض.

### تشغيل التجربة

\`\`\`cmd
git fetch origin
git switch --track origin/feature/automatic-done-print-ledger-contact-sync
bun install --frozen-lockfile
npm run dev
\`\`\`

بيانات السجل في \`.data/print-ledger.sqlite\`. النسخ الاحتياطي يشمل هذا الملف إضافة إلى قاعدتي \`printing-management.sqlite\` و\`print-intake.sqlite\`؛ استعمل أدوات نسخ SQLite المناسبة عند تشغيل WAL.

**تنبيه:** حدث نقل الملف إلى done ليس دليلاً من عدّاد الطابعة على عدد النسخ المطبوع، والبيانات المالية الاختيارية في سجل الطباعة ليست بديلاً من قيود الفواتير والدفعات الرسمية.
