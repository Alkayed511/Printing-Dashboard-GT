# Golden Target — توسعة إدارة المطبعة

## ماذا تضيف إلى المشروع الحالي؟

تضيف شاشتين إلى تطبيق Printing-Dashboard-GT الحالي دون تغيير تصميم Kanban:

- **حاسبة الطباعة:** متر مربع، متر طولي، رول مع حساب عدد القطع على عرض الرول (وأفضلية الدوران)، شيتات / ألواح، وتسعير بالقطعة. تسمح بعدة بنود وباختيار الطابعة والخامة وتكلفة الإنتاج والربح وهدر المواد والخصم والضريبة. تحفظ الحسابات وتحوّلها إلى عروض أسعار وأوامر طباعة في Kanban، وفواتير.
- **إدارة العملاء:** إضافة وتعديل وأرشفة عميل، معلومات الاتصال والرقم الضريبي، سجل الحسابات والعروض والفواتير، تسجيل دفعات واستردادات، كشف حساب PDF/CSV، وربط أمر الإنتاج الحالي بالعميل عبر رقم ثابت لا عبر الاسم.
- **قاعدة بيانات دائمة SQLite:** باستخدام Node.js 22.13+ مدمج في Node دون خادم قاعدة بيانات خارجي، وجداول للعملاء والحسابات والعروض والفواتير والدفعات والخامات وأوامر الإنتاج وروابط العملاء، مع معاملات SQLite وتفعيل WAL.
- **حماية:** تسجيل دخول مدير وكوكي HTTP-only و SameSite Strict، وحماية واجهات API الحالية والجديدة. يفشل النظام إلى وضع مغلق إذا لم تُعد الأسرار.

## التشغيل بعد دمج التحديث في GitHub

1. أنشئ ملف `.env` في جذر المشروع اعتماداً على `.env.management.example`، وأضف كلمة مرور قوية في PRINT_ADMIN_PASSWORD وسراً عشوائياً طويلاً في PRINT_SESSION_SECRET. لا ترفع ملف `.env` إلى GitHub.
2. استخدم Node.js 22.13 أو أحدث، وشغّل: `npm ci`، ثم `npm run lint`، ثم `npm run test:management`، ثم `npm run build`.
3. شغّل `npm run dev` محلياً واختبر حسابات الطباعة والعميل والدفعات، ثم انشر في بيئة تدعم حفظ SQLite دائماً.
4. لا تنشر قواعد Firestore الجديدة قبل التحقق من توقف المزامنة القديمة.

## حفظ البيانات والنسخ الاحتياطي

- البيانات الجديدة تحفظ على الخادم في `.data/printing-management.sqlite` مع ملفات `-wal` و `-shm` إذا كانت SQLite تستخدم WAL. المجلد مستثنى من Git.
- يمكن تنزيل تصدير JSON من زر **نسخة احتياطية** بعد تسجيل الدخول. هذا تصدير للبيانات، وليس نسخة تامة تضمن إعدادات التطبيق. خذ نسخة من ملف SQLite عبر إيقاف الخادم أو استخدام آليات SQLite الآمنة للنسخ.
- إعدادات لوحة الإنتاج القديمة أصبحت تحفظ في جدول `app_settings` بدلاً من الاعتماد على قاعدة Firestore المفتوحة. تحتاج إعداداتك القديمة إلى مراجعة يدوية بعد التحديث إذا لم تكن محفوظة محلياً.
- روابط العملاء لطلبات الملفات تُعرف بمعرّف ثابت ناتج عن تاريخ مجلد العمل ونوع الطابعة واسم الملف. **إذا تغيّر اسم الملف أو موقعه في التاريخ أو الطابعة سيتغير المعرف**، ويجب إعادة الربط.

## تحذيرات التوافق والأمان

- التثبيت يستبدل ملف `firestore.rules` بقواعد deny-all كي لا تبقى إعدادات Firestore قابلة للقراءة والكتابة دون مصادقة. **هذه الخطوة قد توقف مزامنة إعدادات اللوحة أو ملاحظات الصوت بين مثيلات الخادم التي كانت تعتمد على Firestore**. اختبر بعناية قبل نشر القواعد على مشروع Firebase فعلي، واستخدم خادماً واحداً يدير ملفات الإنتاج.
- إعداد `PRINT_ENABLE_LEGACY_FIRESTORE=true` مخصص فقط للحالات التي أعيد تأمين قواعد Firestore فيها ومصادقة الخادم؛ لا تفعّله مع قواعد عامة أو مع قواعد deny-all.
- استخدم HTTPS إذا كان الوصول من خارج جهاز موثوق، مع `PRINT_SECURE_COOKIES=true`، ولا تفتح منفذ Express للإنترنت بلا جدار ناري / Reverse Proxy. استخدم كلمة مرور قوية.
- نموذج الحساب بالرول يحسب تعشيق مستطيلات وتدويرها، ولا يقدّم تعشيقاً هندسياً حراً أو ترتيباً فيزيائياً للقطع على الرول. الأسعار تقديرات تعتمد على المعطيات وليست قراءة فعلية لعداد الطابعة.
- لن تصدر الفاتورة تلقائياً قبل اعتماد عرض السعر. لا يسمح النظام بتكرار فاتورة للعرض نفسه أو بتسجيل دفعة تتجاوز الرصيد.
- النظام يوفر حساب مدير واحد للمرحلة الحالية، وليس صلاحيات موظفين متعددة. يلزم تصميم RBAC ومصادقة المستخدمين قبل إطلاق النظام للعاملين بحسابات منفصلة.
- ملفات الإنتاج التي يحفظها النظام من العروض هي أوامر مرجعية في Kanban دون إنشاء ملفات PDF/AI على مجلد الشبكة؛ يجب على الفني إرفاق الملف الحقيقي على المسار الحالي إذا لزم إرسال ملف إلى الطابعة.
- لا يشمل هذا الإصدار إصدار فواتير إلكترونية معتمدة ضريبياً؛ PDF هنا نموذج تجاري قابل للطباعة ويحتاج المراجعة الضريبية حسب القوانين المحلية.

## الرجوع للإصدار السابق

يحفظ المثبّت نسخة من الملفات التي غيّرها داخل `.gt-upgrade-backup-YYYYMMDD-HHMMSS` في المجلد الأصلي. لإلغاء تركيب التوسعة أعد الملفات من النسخة، ثم احذف ملفات `src/server/*`, `src/types/management.ts`, `src/utils/printMath*` والشاشات الجديدة بعد التأكد أنها لا تتضمن أعمالاً أخرى لك.
