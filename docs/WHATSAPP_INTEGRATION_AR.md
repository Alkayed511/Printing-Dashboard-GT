# ربط واتساب واستلام التصاميم — Golden Target

## كيف يعمل النظام؟

1. **العميل من واتساب:** عند تفعيل Meta WhatsApp Business Platform، تصل رسائل العميل الجديد عبر Webhook مع الرقم واسم واتساب ونص الرسالة وبيانات مرفق التصميم. تتم إضافة العميل إلى سجل العملاء أو ربطه بالعميل الموجود بناءً على رقم واتساب، **دون تعديل أسماء العملاء التي سبق تسجيلها يدوياً**.
2. **العميل اليدوي:** إذا كنت تستخدم واتساب العادي أو لم تفعّل Meta API، أضف العميل من شاشة **واتساب واستلام التصاميم** أو **إدارة العملاء** وسجّل رقمه. يمكنك فتح محادثته عبر زر «فتح محادثة العميل». لا يستورد هذا الخيار محادثاته تلقائياً.
3. **إنشاء الطلب:** اختر الرسالة الواردة ثم «إنشاء طلب»، أو «طلب يدوي جديد». يحصل الطلب على رقم مستقل مثل \`GT-...\`.
4. **التعديل:** احفظ كل نسخة عند تعديل الاسم، المقاسات، الطابعة أو الملاحظات. تبقى النسخ السابقة محفوظة تحت نفس رقم الطلب.
5. **نقل الملف:** بعد حفظ التصميم النهائي، انقل الملف بالطريقة المعتادة عبر الشبكة المحلية إلى مجلد الطابعة.
6. **ربط الإنتاج:** عندما تظهر الملفات الجديدة في Kanban، اختر **عدة ملفات دفعة واحدة** من قائمة «إضافة ملفات أخرى». يحفظ النظام اسم كل ملف وطابعته ومعرفه تحت رقم الطلب الثابت. يمكنك إضافة ملفات لاحقاً.
7. **الموظف:** ينفّذ الطباعة كالمعتاد وتظهر حالة الملف على Kanban. يمكنك متابعة الطلب المستقل في شاشة الاستلام. **إذا تغير اسم الملف أو نقله مرة ثانية، يجب إعادة تحديد الملف الجديد يدوياً**؛ ما زال رقم الطلب ثابتاً.

## تشغيل التجربة في VS Code

هذه الميزات تعمل الآن **يدوياً دون أي مفاتيح واتساب**. استخدم Node.js 22.13+ وBun:

\`\`\`cmd
git fetch origin
git switch feature/whatsapp-intake-stable-production-requests
bun install --frozen-lockfile
npm run lint
npm run test:management
npm run dev
\`\`\`

افتح \`http://localhost:3000\` وسجل الدخول بكلمة مرور \`.env\`. شاشة «واتساب واستلام التصاميم» موجودة في القائمة الجانبية.

## تفعيل الاستقبال التلقائي عبر Meta (اختياري)

**هذه الخطوة تتطلب حساب WhatsApp Business Platform / Cloud API، وليست قراءة واتساب شخصي أو تطبيق WhatsApp Desktop.** لا تستطيع واجهة Cloud API قراءة محادثات التطبيق الشخصية أو استرجاع أرشيف محادثات قديمة لم يتم إرسالها عبر واجهة API.

1. أنشئ/هيّئ حساب Meta Developers وWhatsApp Business Platform الخاص بالشركة.
2. أنشئ رمز تحقق عشوائياً \`WHATSAPP_VERIFY_TOKEN\`، واحصل من Meta على \`WHATSAPP_APP_SECRET\` و\`WHATSAPP_ACCESS_TOKEN\` مع صلاحيات الحساب اللازمة.
3. ضع المتغيرات في ملف \`.env\` الخاص بالخادم (لا ترفعها إلى GitHub):
   \`\`\`dotenv
   WHATSAPP_VERIFY_TOKEN=REPLACE_WITH_PRIVATE_VERIFY_TOKEN
   WHATSAPP_APP_SECRET=REPLACE_WITH_META_APP_SECRET
   WHATSAPP_ACCESS_TOKEN=REPLACE_WITH_META_SYSTEM_USER_ACCESS_TOKEN
   WHATSAPP_GRAPH_VERSION=v24.0
   \`\`\`
4. أنشئ **عنوان HTTPS عام** يصل إلى خادم البرنامج (مثلاً عبر استضافة آمنة أو tunnel موثوق)، وثبّت شهادة TLS والقيود اللازمة. واتساب لا يستطيع الوصول مباشرة إلى \`http://localhost:3000\` أو إلى عنوان IP محلي.
5. سجّل Callback URL في Meta: \`https://YOUR-DOMAIN/api/whatsapp/webhook\`، وضع Verify Token نفسه، واشترك في حدث \`messages\` الخاص بحساب WhatsApp Business الصحيح.
6. أرسل رسالة تجريبية ورقة تصميم إلى رقم العمل، ثم افتح «واتساب واستلام التصاميم» واضغط «تحديث».

**الأمان:** يفحص الخادم توقيع \`X-Hub-Signature-256\` قبل قبول أي رسالة. تُستخدم مفاتيح Meta داخل الخادم فقط، ولا تُرسل للمتصفح. كل بيانات العملاء ورسائلهم وطلبات الإنتاج تخضع لجلسة إدارة البرنامج. إذا لم تضبط أسرار واتساب، يكون Webhook معطلاً.

### المرفقات والنسخ الاحتياطية

- يخزن النظام **معرّف المرفق ومعلوماته** (اسم الملف والنوع) ولا ينزّل المرفقات تلقائياً. بعد تفعيل \`WHATSAPP_ACCESS_TOKEN\` يمكن تنزيل المرفقات المتاحة من Meta من شاشة الاستلام (حد تنزيل 40MB). المرفقات الأكبر تُنزل من واتساب بالطريقة المعتادة.
- لا تضع مرفقات التصاميم في مجلد بيانات SQLite تلقائياً. احفظ نسخة التصميم المصرّح بها في مجلد العمل المعتاد.
- هناك قاعدة بيانات جديدة \`.data/print-intake.sqlite\` **بالإضافة** إلى \`.data/printing-management.sqlite\`. خذ نسخاً احتياطية آمنة من الملفين عند توقف البرنامج، أو عبر أدوات SQLite المخصصة مع WAL.
- يمكن تصدير نسخة JSON من الطلبات والرسائل عبر \`/api/management/intake/export\` بعد تسجيل الدخول.
- إرسال رسائل أو عروض أسعار **تلقائياً** إلى واتساب غير مفعّل في هذا الإصدار؛ التواصل الحالي من زر فتح المحادثة. إرسال رسائل استباقية يتطلب موافقة العميل وقوالب Meta المعتمدة عند الحاجة، وليس مجرد رقم هاتف.

## الخصوصية والتشغيل الفعلي

- لا تضع قاعدة البيانات أو مفتاح \`.env\` على مشاركة عامة. احصر الوصول على الكمبيوتر/شبكة موثوقة، واستخدم HTTPS عند الإتاحة خارج localhost.
- التحقق من المستخدمين في هذا الإصدار ما زال حساب مدير واحد، وليس حسابات منفصلة لكل موظف. وسّع نظام الأدوار قبل إطلاق النظام على موظفين مختلفين.
- ربط الطلب بملفات Kanban يتم يدوياً، وليس اكتشافاً آلياً لتطابق تصميم واتساب مع ملف تغيّر اسمه. هذه الطريقة تتجنب أخطاء نسبة ملفات إلى عميل آخر.
- **إذا تغيّر اسم الملف أو لم يعد مرئياً في التاريخ المختار:** يحتفظ الطلب بسجل الملف القديم (الاسم والطابعة). يظهر «غير ظاهر حالياً»، ويمكنك اختيار «تعديل» لاستبدال ارتباطه بالاسم الجديد، مع الاحتفاظ بتاريخ الاستبدالات. ولا يُزال الارتباط تلقائياً.
- **لإلغاء الربط:** زر «حذف الربط» يحذف ارتباط ذلك الملف بالطلب فقط، **ولا يحذف الملف من القرص أو مجلد الطابعة**. يمكن أيضاً تعديل الملاحظة دون تغيير الملف.
- الملف الواحد لا يمكن إضافته مرتين للطلب نفسه؛ والملف المرتبط بعميل مختلف لا يقبل إعادة نسبته آلياً.
- عدد الملفات المرتبطة يصل إلى 100 ملف لكل طلب، وتتم الإضافة على دفعات من 25 ملفاً.
- إذا كان رقم واتساب نفسه مسجلاً لأكثر من عميل، لا يختار النظام أحدهما تلقائياً؛ يجب تعيين الرسالة للعميل الصحيح.
